# Storybook governance panel accessibility and usability audit

Date: 2026-10-27. Audited local source `eb2e4d7` using the actual dogfood report and the local Storybook manager in the Codex in-app browser. This is a targeted audit, not a WCAG conformance assessment, full screen-reader test, visual-regression suite or human acceptance. No implementation changes were made.

Follow-up verification is recorded separately in [Storybook freshness and accessibility verification](storybook-freshness-accessibility-verification.md).

## Findings

1. **High — an expired report can continue to show ready while the panel remains open.** A temporary report was loaded while still within the 24-hour freshness limit. At 16:44:50 UTC, more than nine seconds after its 16:44:40 expiry, the panel still displayed `ui.button` and `Gate: ready`; selecting Reload then changed it to “Unverified — this report is older than 24 hours.” The panel calls `loadReport` only on initial load or explicit refresh ([manager.tsx](../../packages/storybook-addon/src/manager.tsx#L22)); the decoder checks age at load ([report.ts](../../packages/storybook-addon/src/report.ts#L23)). The release gate remained blocked, but the readiness indication was stale. Source inspection also shows sidebar labels poll every 60 seconds with a 30-second cache, so they can remain stale temporarily; this sidebar expiry delay was not timed in the browser. Validation uses a time captured before fetch, so a report crossing expiry while a slow response is in flight needs a regression. The release subreport also has a separate timestamp.
2. **High — keyboard focus is lost when a ready report is reloaded.** From the selected Governance tab, Tab reached Copy ID and Reload report. Pressing Enter on Reload replaced the ready panel and focus moved to the page's web area/body. Recovering from a stale report to ready also lost focus. The loading/error and ready branches render different button subtrees ([manager.tsx](../../packages/storybook-addon/src/manager.tsx#L56)). Keyboard users must find their position again.
3. **Medium — copy feedback belongs to the previous component.** Clicking Copy ID for `ui.button` changed the control to “Copied ID”; selecting the existing `ui.select` story kept that label even though the selected ID changed. The copied state is not reset with component identity ([manager.tsx](../../packages/storybook-addon/src/manager.tsx#L21)). Clipboard rejection also lacks explicit error feedback in source, although rejection was not simulated in the browser.
4. **Medium — an unmapped component cannot refresh from its panel.** The `ui.unmapped` story displayed “Unverified component” and “No registry decision for ui.unmapped,” with no Reload report control. If the report is corrected, a full page reload or report URL change can fetch it again; switching between stories with the same URL does not necessarily refetch ([manager.tsx](../../packages/storybook-addon/src/manager.tsx#L80)).
5. **Medium — expired release-snapshot guidance is ambiguous.** When both governance and embedded release timestamps were stale, the panel displayed “Release candidate snapshot is stale, invalid or belongs to another source” without the regeneration instruction shown for a report-only expiry. The release check takes precedence over the report-age message ([report.ts](../../packages/storybook-addon/src/report.ts#L30)). A valid report with only its governance timestamp stale did show the clearer “Generate a current snapshot” message.
6. **Follow-up — evidence provenance is missing from the panel contract.** The panel's evidence table contains check, result, evidence ID and reason, but not age, producer or source link. The handoff requests those fields; the generated report contract currently contains evidence IDs only, while the core Evidence type has producer, observed time and optional source URL ([generated protocol](../../packages/protocol/src/generated.ts#L35), [core evidence](../../packages/core/src/domain.ts#L86)). Adding these fields requires a separately designed compatible report/protocol change and must preserve unknown/unverified values rather than inventing provenance.

## What was observed

- Button displayed stable / ready while its exact release candidate was blocked; Select displayed candidate / blocked; the unmapped story displayed unverified. Readiness, release and publication/deployment were presented separately.
- A missing report returned an unverified HTTP 404 message and a Reload report control. A report-only stale fixture returned unverified plus regeneration guidance. An embedded stale release snapshot returned the generic message described above. Reloading the restored real report returned to the ready view.
- At a 640 × 800 viewport the evidence table overflowed horizontally (302 px visible / 433 px content). In this browser, Tab reached its scroll container and Right-arrow scrolling moved it; the accessibility tree described the target only as a container. Disclosure summaries were keyboard reachable and Enter expanded the candidate details. Other browsers and screen readers were not tested.
- The selected story's sidebar entry exposed lifecycle, readiness and release state in its accessible name. The panel uses native buttons, headings, `<details>` and a table with `<th>` elements. The browser accessibility snapshot exposed the table's header row as cells; that observation alone does not establish screen-reader failure or a conformance result.
- A limited dark-theme contrast calculation for the owner/target text used the observed foreground `rgb(201,204,207)` at opacity 0.72 on `rgb(34,35,37)`, yielding approximately 5.75:1. This is one sample, not a full contrast or zoom assessment.

For missing/stale tests, the ignored generated report was temporarily replaced with controlled data. The original was restored byte-for-byte; SHA-256 before and after was `d4eeb105294788230580eea4c3553a4ac26a8f916671044bd41a04d46e67dba5`. The report was freshened from the actual current source before testing. No remote, credentials, publication or deployment were used.

## Recommended bounded fix

First fix report freshness and interaction behavior: invalidate the open panel and sidebar labels when the earliest governance or release timestamp expires, validate freshness after fetch and recheck on visibility return; retain or deliberately restore keyboard focus and announce loading, success and error; reset copy feedback on component changes, prevent late clipboard completions from updating the wrong component and expose clipboard failures; provide Reload in the unmapped state; and make stale release recovery actionable. Add deterministic timed and rendered interaction tests plus browser keyboard checks for those regressions. Preserve the distinction between unverified observations, readiness and release eligibility. Re-run local checks/builds and the dogfood browser audit.

Treat evidence age/producer/source-link support as a second slice: design report/protocol versioning and compatibility negotiation, then update the panel with truthful fallback for missing values and accessibility tests. The existing schema rejects additional properties, so adding fields to schema v1 without a migration strategy would break older validators. Formal assistive-technology, broader themes, zoom/contrast, responsive and human acceptance remain separate qualification work.
