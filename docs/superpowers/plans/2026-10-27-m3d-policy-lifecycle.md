# M3d Synthetic Owner Policy Lifecycle Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox syntax.

**Goal:** Model signed, two-owner policy lifecycle and atomic synthetic checkpoint/challenge transitions without creating production authority.

**Architecture:** Add one private offline package. It verifies exact signed root/policy/challenge bytes against separately supplied synthetic trust inputs, models a versioned immutable in-memory store and revalidates transitions at application time. Results are fixture-only and disconnected from release checks and MCP.

**Tech Stack:** Bun 1.4.2, TypeScript, Moon, Effect Schema, Node-compatible Ed25519, tsdown, Vitest, oxlint/oxfmt.

**Spec:** `docs/superpowers/specs/2026-10-27-m3d-owner-policy-operations-design.md`, approved by user; reviewer-policy changes require two independent owner approvals.

## Global constraints and wire profile

- Synthetic inputs only: no production root, real keys, GitHub requests, credentials, filesystem trust, persistence, release/MCP capability, push or publish. A fixture result is never real human identity, independent owner control, protected storage, trusted time, current policy or approval. Caller-supplied state is simulated, not a trust anchor.
- A private `@governanator/fixture-policy` package exports `applyFixturePolicyTransition(input: unknown): FixturePolicyResult` and documented types. Return schemaVersion 1, assurance `fixture-only`, status `committed | insufficient_evidence | interrupted` and fixed non-sensitive reason codes. Failed or pre-commit interrupted transitions return the unchanged store; post-commit crash simulation returns committed store with explicit committed status. No arbitrary exception text or partial state.
- Every signed object is a bounded UTF-8 JSON byte sequence, validated for duplicate decoded property names, unsafe integer lexemes, invalid UTF-8, unknown or extra fields and strict schemas. Copy bytes without invoking caller-controlled iteration, reject shared backing across realms, bound 64 KiB per metadata object and 32 signatures, and verify exactly those bytes. Ed25519 key format is canonical DER SPKI base64 with `sha256:` SHA-256 fingerprint; verify 64-byte signatures with `node:crypto` using null algorithm. Domain separate signing using DSSE PAE over exact bytes and payload types `application/vnd.governanator.fixture-root.v1+json`, `application/vnd.governanator.fixture-policy.v1+json`, and `application/vnd.governanator.fixture-enrollment.v1+json`; signature entry `{keyId, signature}` uses canonical base64, no claimed role or keyId confers authority. Authenticated payload bytes are parsed/checked after signature verification, except independently injected synthetic roots needed to select verification keys.
- JSON root payload `{schemaVersion:1, repository:{provider:"github",host:"github.com",id:positive-safe-int}, policyId:string, version:positive-safe-int, previousDigest:hash|null, currentPolicyDigest:hash|null, issuedAt:utc, expiresAt:utc, threshold:integer, administrators:[{actorId:positive-safe-int,keyId:hash,publicKey:base64}]}`; bound 2–32 admins, unique actor IDs and keys; validate fingerprints and `2 <= threshold <= admin count`. Timestamps canonical UTC millisecond ISO, no future issue, expiration strictly after injected now and issue, interval at most 24h.
- JSON policy payload `{schemaVersion:1, repository, id:string, revision:positive-safe-int, previousDigest:hash|null, issuedAt:utc, expiresAt:utc, assignments:[{actorId:positive-safe-int,keyId:hash,publicKey:base64,status:"active"|"revoked",roles:["design-system-owner"|"api-owner"]}]}`; bound 0–100 assignments, unique actor/key, no duplicate role; validate fingerprints and time identically. Root and policy scope must match externally supplied expected repository and policy ID. Digest is `sha256:` of exact copied signed JSON bytes. Metadata root and policy arrays of signatures are unique by key and actor; count at most once per distinct administrator.
- Enrollment challenge is exact signed JSON `{schemaVersion:1, purpose:"fixture-reviewer-enrollment", repository, policyId, epoch:nonnegative-safe-int, revision:positive-safe-int, previousPolicyDigest:hash, nextPolicyDigest:hash, actorId:positive-safe-int, keyId:hash, nonce:string, issuedAt:utc, expiresAt:utc}`. The epoch must match the independently supplied synthetic witness and current store, so a pre-recovery challenge cannot be replayed after recovery. Nonce is 32 lowercase hex characters; lifetime <=24h and valid at supplied clock. Proof is signed by the proposed reviewer key over enrollment PAE. A separately supplied pending challenge record must match every challenge byte/digest; no valid enrollment or rotation without it.
- Synthetic store includes `version`, recovery `epoch`, current exact root/policy bytes, checkpoint `{rootVersion,rootDigest,policyRevision,policyDigest,lastTime,repository,policyId,epoch}`, bounded pending and consumed challenge identifiers. An independently injected synthetic state witness binds the current scope, epoch, store version, checkpoint and consumed-challenge commitment; it advances after each modeled commit and detects restoring an older store within the same epoch. Synthetic root and policy signature checks happen before storing. Checkpoint hashes and IDs must match stored bytes; no missing, stale, conflicting or suspect state accepted by ordinary transitions. Freshness is synthetic only; local caller owns state and can fabricate it.
- Input contains an externally supplied synthetic expected repository/policy, independently injected fixture anchor for bootstrap, existing store or null, `expectedStoreVersion`, canonical injected `at`, transition and `crashMode: "none" | "before" | "after"`. Bootstrap accepts only null store/version 0, exact injected anchor root and root-signed revision-1 policy with no reviewer assignments; root previous and current policy digests are null. Store version increments once only on committed mutation.
- Policy update requires exact revision +1 and predecessor digest, current-root threshold signatures; action-specific diff permits precisely one actor change: `enroll` adds a new active actor/key with matching pending challenge and possession proof; `rotate` replaces one actor key and consumes matching new-key challenge with no overlap; `roles` modifies only one actor's roles; `revoke` changes only that actor's status to revoked; `remove` removes only that actor. No unrelated edits or ambiguous status/roles change. Preserve root bytes/version and epoch. Each action verifies fresh root, policy, time and checkpoint.
- Root update requires exact version +1, predecessor root digest and `currentPolicyDigest` equal to the current exact policy digest, signed by both distinct old and new administrator thresholds over the exact same successor bytes; new threshold >=2; reviewer policy unchanged and current, checkpoint root digest/version advance. Reject mismatched expected scope, same-version differing bytes, gaps and non-monotonic clock.
- Recovery is a distinct action, never inferred from a candidate: a separately injected synthetic recovery authority of at least two unique owner keys and minimum epoch witnesses a statement `{schemaVersion:1, purpose:"fixture-policy-recovery", repository, policyId, priorEpoch, nextEpoch, rootDigest, policyDigest, auditId, issuedAt, expiresAt}` signed over DSSE PAE with payload type `application/vnd.governanator.fixture-recovery.v1+json`. Require nextEpoch=priorEpoch+1 and a separately supplied synthetic witness carrying the prior epoch and protected time floor, including when the store is missing or suspect. Reject a recovery clock earlier than that floor. Verify two distinct recovery owners and the synthetic witness independent of candidate, require fresh valid initial root and root-threshold-signed revision-1 policy with no reviewer assignments, reset into new epoch; old/missing checkpoint alone cannot approve recovery. Explicitly model lack of independent witness as insufficient. No claim simulated authority protects real recovery or rollback.
- CAS/atomic semantics: `applyFixturePolicyTransition` takes the actual caller-supplied current store and expected version, independently recomputes/validates the entire transition against it at call time; never trust standalone mutable `verified`/`proposal` flags. Version mismatch rejects; before-crash leaves store/checkpoint/pending and consumed challenges unchanged; successful/after-crash commits full new state atomically with challenge consumption. The immutable returned copy must not alias caller buffers/objects. Two evaluations from one version: applying the second to first's returned store with stale expected version fails. No runtime persistence or concurrent locking is claimed.

## Review focus

- Signed malformed UTF-8, duplicate fields, unsafe numeric IDs, bad signature, spoofed keyid and custom byte/array iterators must fail closed.
- Duplicate administrator keys/actors or repeated signature cannot satisfy the two-owner threshold; threshold reduction to one fails even with old/new approvals.
- Replay, key substitution, revision or scope mismatch and concurrent challenge reuse cannot commit or consume a challenge.
- Missing/rolled-back checkpoint, root/policy equivocation, stale time, recovery without independent fixture authority and older restored state cannot silently advance.
- Forged lifecycle output or proposal injected into a real candidate check and saved MCP path cannot authorize release; static package guard is a targeted check, not a sandbox.
