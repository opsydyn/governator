# Governator 0.2.0 publishing workflow

Approved scope: prepare and rehearse locally; retain the exact candidate archives, commit on local main, and defer manual acceptance. No push, hosted dispatch, release creation/upload or npm publication is authorized by this preparation.

## Design

Use the retained 0.2.0 inventory from source cfd81a9 as a tracked hash pin. A private Node 24 adapter verifies all archives before external operations, preflights all three versions, skips exact existing versions, stops on conflicts or uncertainty, and checks npm tarball bytes after each upload. It never builds or packs. A single-maintainer workflow defaults to rehearsal, requires an explicit publication confirmation for live operation, and exposes NPM_TOKEN only to the live step.

Transfer the existing archives through a draft GitHub release named governator-v0.2.0-candidate when remote staging is separately authorized. The tag is a locator; the tracked hashes select the bytes. No release asset or candidate record downloaded from GitHub can redefine those hashes. npm provenance describes the later publishing workflow; it is not proof of the earlier local build.

Use Node built-ins so the credential-bearing job installs no project dependencies. This is a private filesystem/subprocess/network adapter; public packages and retained archives stay unchanged. It assumes the operator controls the runner and local files; it does not restore sealed-file custody or dual control.
