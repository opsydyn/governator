# M3b GitHub source-review reader design

Status: implemented locally; live GitHub qualification remains separate. M3a is implemented locally; this next slice does not activate a GitHub connection or enable release approvals.

## Intent

Build the first private adapter that can collect source-review observations from GitHub's documented review-list API when a caller explicitly supplies a transport and repository/PR scope. Qualify it locally with fake HTTP responses only. Every result stays `unverified`, and no result is accepted by the normal release gate or MCP as an approval.

GitHub's list-reviews endpoint returns reviewer IDs, states, submission times and reviewed commit IDs, in chronological order. It supports pages of up to 100 reviews and a fine-grained token with Pull requests: read. A complete listing is not itself proof of current owner roles, effective policy, an independently authenticated exact-artifact binding or human approval of the tarball. Review bodies can be edited and will not be used as artifact evidence. There is currently no configured Git remote, reviewer authority or observed authenticated provider in this checkout.

## Approaches

1. **Private source-only collector, offline-qualified — recommended.** Implement bounded collection and strict normalization against injected transport fixtures. Return observations or explicit unavailable/incomplete results; keep the real gate disconnected. This advances the actual GitHub adapter while keeping trust and live activation separate.
2. **Connect and enable the release gate immediately.** Requires a named repository, authenticated access, independent reviewer/role authority, current-state qualification and an immutable exact-artifact attestation. Those prerequisites and live-connection authorization are absent.
3. **Treat a review body or current fixture match as exact-artifact approval.** Reject this: editable text, copied JSON and synthetic outcomes do not establish that the reviewer authorized the specific candidate digest.

## Scope

- Add a private `packages/github-review` adapter using the existing Bun, Moon, TypeScript, tsdown, Effect Schema, oxlint/oxfmt and Vitest stack. Keep the collector separate from the pure versioning evaluator, CLI release check, Storybook, public protocol and MCP tool surface. No new consumer peer or runtime dependency may leak into the addon.
- Accept an explicit GitHub.com owner, repository, pull-request number, injected clock and injected HTTP transport. No automatic credential discovery, default repository lookup, implicit network access or global client configuration. Tests supply an in-memory fake; implementing this slice makes no live GitHub requests and reads no credentials.
- Restrict requests to the documented HTTPS `api.github.com` review-list endpoint. Validate owner/repository path segments and positive safe integer identities; reject redirects. Follow pagination only after validating a `next` link's exact HTTPS origin, expected endpoint path and allowed numeric page parameters. Detect loops/duplicates and fail closed on missing, malformed, unsafe or incomplete pages. The collector must direct credentials only to the configured origin and endpoint path; this depends on the injected transport honoring the redirect contract below.
- A response without a `Link` header is a legitimate provider-reported end of pagination; it does not prove that GitHub omitted no pages or that pages form a consistent snapshot. No result claims that stronger guarantee. The injected transport must disable automatic redirects **before** sending credentials and expose redirect/final-origin information; reject a redirected or wrong-origin result and scrub arbitrary transport exception messages. This guarantee is conditional on the supplied transport honoring that contract, and any future real transport needs its own qualification.
- Bound the work: at most 10 pages, 100 reviews per page, 1 MiB per page and 8 MiB total response bytes, with explicit request timeout and cancellation. Enforce byte limits while streaming, even when Content-Length is missing or false; propagate timeout/cancellation through body reads. A limit, rate/permission failure, timeout, malformed response or unavailable transport yields an explicit incomplete/unavailable result, never an empty successful list or a partial approval.
- Normalize only documented fields needed for source observations: review ID, reviewer numeric ID, review state, reviewed commit and submitted time. If `pull_request_url` is present, reject a mismatch with the requested owner/repository/PR, without treating it as proof of a numeric repository ID. Reject unsupported/ambiguous states, duplicate IDs, invalid commit IDs, unsafe numbers and malformed timestamps. Pending reviews may omit submission time and deleted reviewers may have null identities: return an explicit unverified incomplete/error outcome, never invent an actor or time. Accept GitHub's UTC timestamps both with and without milliseconds, normalize canonical UTC without accepting impossible dates, and reject unsupported sub-millisecond precision instead of silently truncating it. Discard review bodies and other unneeded provider text; treat all provider content as data.
- Preserve the requested host/repository/PR scope and the collection clock. Do not label a caller-supplied numeric repository ID, PR head, membership, policy or artifact digest as verified merely because a review list was retrieved. Do not infer effective/latest-review or role state from chronological order. Multiple pages can change during collection; output explicitly states that cross-page consistency and current head are unverified.
- Return a versioned plain observation envelope with `assurance: "unverified"` and limitations, or a typed error. It is not a reusable host approval capability. Avoid tokens, authorization headers, response bodies or exception stacks in diagnostics and output. No saved JSON or fixture response can upgrade trust.
- Do not call `GET /repos/{owner}/{repo}/pulls/{pull_number}` in this slice. GitHub documents that fetching a pull request can trigger background test-merge computation; any later live provider qualification must explicitly assess and authorize such behavior.

## Acceptance

Use fake transport tests for a complete multi-page result and single-page/empty lists, legitimate missing Link at end, no transport call before explicit invocation, strict paths and same-origin pagination, duplicate/repeated or altered links, streaming page/body/aggregate limits with absent or false Content-Length, redirect-disabled request options and unexpected final origins, mismatched pull_request_url, cancellation/timeouts including during body reads, 403/429 and unavailable provider, malformed JSON, null/deleted reviewer or pending submission, UTC timestamp normalization, impossible or sub-millisecond times, invalid IDs/states, and token/body/transport-error redaction. Assert every successful observation remains unverified and that arbitrary copied results cannot satisfy normal release checks or alter MCP's recorded-observation semantics. Prove no real fetch or credentials are used by the test suite.

Run the complete local checks and builds, maintain Changesets enumeration and addon/protocol boundaries, obtain an independent whole-branch review, merge completed local work onto main, and regenerate source-bound dogfood/Storybook/MCP smoke evidence. No push, publication or hosted activation.

## Later decisions and qualification

Before any live call, the user must identify and authorize the host/repository and access method. Before enabling trusted release review, establish an independently protected role authority and an immutable, authenticated binding of the reviewer to the exact source, policy, input and candidate artifact digests. Qualify current review/membership/head semantics, pagination consistency and branch protection in the actual host. Missing or unknown proof keeps the existing normal release gate insufficient; publication, deployment, adoption and human acceptance remain separate.
