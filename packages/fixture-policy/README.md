# Fixture policy lifecycle

This private, offline package simulates a signed reviewer-policy lifecycle. Its results are **fixture-only**: injected keys, state, clock and epoch witness prove no human identity, independent control, protected storage, trusted time, current policy or release approval. It has no production integration, persistence, network or credential access.

`applyFixturePolicyTransition(input: unknown): FixturePolicyResult` returns `{schemaVersion: 1, assurance: "fixture-only", status, reasons, store}`. Status is `committed`, `insufficient_evidence`, or `interrupted`; failure reasons are `invalid_evidence` and pre-commit interruption uses `interrupted_before_commit`. A validated transition with `crashMode: "after"` returns its committed state; `"before"` returns the unchanged copied input store. This is a caller-supplied in-memory CAS simulation, not a lock or durable transaction. Uncopyable malformed input can yield a null store.

Inputs are exact objects with fields:

- `schemaVersion: 1`, `expected: {repository, policyId}`, `at` (canonical UTC milliseconds), `store` (previous result or null), `expectedStoreVersion`, and `crashMode: "none" | "before" | "after"`.
- `anchor`: a separately injected signed initial root envelope for epoch 0; it may be null for independent recovery and subsequent recovered-epoch transitions. `epochWitness: {repository, policyId, epoch}` is separately supplied; its epoch must equal the current store epoch (or the prior epoch during recovery). Bootstrap requires epoch 0.
- `storeWitness: {repository, policyId, epoch, version, rootDigest, policyDigest, lastTime, consumedChallenges}` is separately injected for every transition. Before bootstrap it contains version and epoch zero, null digests/time, and an empty consumed list. For an ordinary transition it must match the current store's checkpoint, version, epoch and consumed challenge IDs; advance it independently after a commit. Recovery checks its version, epoch and `lastTime` floor even when the store or checkpoint is missing or suspect. This independently supplied fixture input is simulated, not protected or authoritative.
- `recoveryAuthority`: null unless recovery is used, otherwise `{owners, threshold, minimumEpoch}`, where owners are independently injected `{actorId, keyId, publicKey}` records and threshold is at least two. Recovered-epoch transitions continue to supply the same independent authority and a witness for the new current epoch.
- `transition` is one of `{kind: "bootstrap", root, policy}`, `{kind: "root", root}`, `{kind: "policy", action, policy, proof}`, or `{kind: "recovery", root, policy, authorization}`. Actions are `enroll`, `rotate`, `roles`, `revoke`, and `remove`; `proof` is an enrollment signed envelope for enroll/rotate and null for other actions.

Each signed envelope is `{bytes: Uint8Array, signatures: [{keyId, signature}]}`. Bytes are exact UTF-8 JSON and signatures are canonical padded base64 Ed25519 signatures over DSSE PAE. Public keys are canonical DER SPKI encoded as padded base64; `keyId` is the `sha256:` lowercase-hex digest of DER. The payload types are `application/vnd.governanator.fixture-root.v1+json`, `application/vnd.governanator.fixture-policy.v1+json`, `application/vnd.governanator.fixture-enrollment.v1+json`, and `application/vnd.governanator.fixture-recovery.v1+json`. Metadata fields and exact constraints are specified in `docs/superpowers/plans/2026-10-27-m3d-policy-lifecycle.md`.

The simulated store holds signed root and policy history, their synthetic transition times, a checkpoint and bounded pending/consumed challenge lists. To simulate an independently issued pending enrollment, the caller supplies a store copy with the exact challenge bytes in `pendingChallenges`; the proof binds those exact bytes, scope, revision, predecessor, successor and reviewer key. The signed challenge includes `epoch`, which must equal the store and witness epoch, so a previous epoch's proof cannot be reused after recovery. The transition consumes it atomically. These caller-controlled records are not protected storage. Arrays are bounded to 32 root versions, 100 policy revisions, 100 pending and 100 consumed challenges; each metadata byte sequence is at most 64 KiB and each signature list at most 32 entries. The overall input is bounded as well. Exhausting a bound fails closed.

Recovery uses a separately injected authority and witness. Its signed statement binds both new payload digests and increments the witness epoch. It reboots into revision 1 with no reviewer assignments; a missing checkpoint alone is never recovery authorization. Restore detection is relative to the independently injected synthetic epoch and store witnesses, which callers must advance to the committed state themselves. None of these fixtures supply a real recovery or rollback guarantee.
